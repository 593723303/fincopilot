## 顺序消融（v1 时期，已退役）

评估集 `v1`：61 题（表格 30 / 多跳 8 / 事实 11 / 拒答 12），全部人工核验并标注页码依据。
表格题按难度分层，其中易混科目 8 题，刻意成对出题压制已暴露的失败模式。

| run | 配置 | 正确率 | 页码召回 | 误答率 | 单题成本 |
|---|---|---|---|---|---|
| 0008 | **基线** `exp02_heading`：top_n=5，预算 6000 | 65.6% [54.1, 77.0] | 38.8% [24.5, 53.1] | 8.3% | ¥0.0024 |
| 0012 | `exp04_wider`：top_n=15，预算 14000 | **86.9% [78.7, 95.1]** | **88.8% [79.6, 95.9]** | 16.7% | ¥0.0062 |
| 0013 | `exp05_rerank_wide`：exp04 + 重排 | 85.2% [75.4, 93.4] | 85.7% [75.5, 95.9] | 8.3% | ¥0.0066 |
| 0014 | `exp00_debug`：exp04 + qwen-flash 生成 | 85.2% [75.4, 93.4] | 86.7% [77.6, 94.9] | 8.3% | **¥0.0013** |
| 0015 | `exp06_fixed`：exp04 + 定长分块 | 88.5% [80.3, 95.1] | 86.7% [76.5, 95.9] | 8.3% | ¥0.0067 |

> run 0005–0007 为早期数据，指标口径与现在不同（当时用文档级召回且阈值未校准），
> 不与上表并列。run 0009–0011 因配置未真正生效而作废，见文末。

### 结论

**1. 放宽截断深度是唯一显著的改进（+21.3 点）**

基线与 exp04 的置信区间完全不重叠（`[54.1, 77.0]` vs `[78.7, 95.1]`），
这是目前唯一可以正式声称提升的改动。页码召回同步从 38.8% 升到 88.8%。

代价：上下文变长，单题成本涨 2.6 倍，误答率从 8.3% 升到 16.7%
（区间重叠，但方向值得警惕——上下文越长，模型越容易从无关内容中"找到"答案）。

**2. 重排无效，已放弃**

exp05 相对 exp04 正确率 -1.7 点、页码召回 -3.1 点、成本 +6%，全部区间重叠。
与隔离测量的结论一致：gte-rerank-v2 在各截断深度下都没有帮助
（top_n=10 时甚至低 9 个百分点）。它是通用语义模型，
对中文财报表格的结构化内容判断不如 RRF 融合，其分数分布也印证这点
（实测集中在 0.11–0.16，区分度极低）。

**3. qwen-flash 可替代 qwen-plus，成本降至 1/4.8**

质量无显著差异（85.2% vs 86.9%，区间大幅重叠），误答率反而更低，
单题成本从 ¥0.0062 降到 ¥0.0013。本场景输入远大于输出
（约 4000 入 / 100 出），而 qwen-flash 的输入单价仅为 qwen-plus 的 1/5。

**4. 分块策略无显著影响，架构假设被推翻**

ADR-005 假定按标题层级分块优于定长分块（保留语义边界），但实测
定长分块 88.5% 对标题分块 86.9%，区间几乎完全重叠——**不仅没更好，
反而略低**。

原因很可能是表格占主导：75–85% 的页面含表格，而表格走 `table_atomic`
整块处理，根本不受文本分块策略影响。再叠加父块还原与 top_n=15 的
宽松截断，残余差异被进一步抹平。

保留 heading 作为默认策略，但理由从「检索更准」改为「产出的
heading_path 对引用展示与人工排查有价值」——这是个诚实的降级，
而不是继续用一个站不住的理由。

**当前最优配置 = exp04 的检索参数 + qwen-flash 生成。**

### 四个因子的边际贡献汇总

| 因子 | 效果 | 结论 |
|---|---|---|
| 截断深度 top_n 5→15 | **+21.3 点**，区间不重叠 | **唯一显著因子** |
| 生成模型 plus→flash | -1.7 点，成本降至 1/4.8 | 质量持平，**显著省钱** |
| 分块策略 heading→fixed | +1.6 点，区间重叠 | 无显著影响 |
| 重排 关→开 | -1.7 点，成本 +6% | 无效，已放弃 |

**三个被广泛推荐的 RAG 优化手段（重排、语义分块、强模型）在本场景
全部无显著收益，真正起作用的是一个没人讨论的参数：送进上下文的块数。**

### 分类指标（run 0012，exp04_wider）

| 类别 | 正确率 | 样本数 |
|---|---|---|
| 表格数值题 | 93.3% | 30 |
| 事实题 | 90.9% | 11 |
| 应拒答 | 83.3% | 12 |
| 多跳推理 | 62.5% | 8 |

表格数值题从 53.3% 升到 93.3%——这是本项目的核心难点，
也是放宽截断受益最大的类别。多跳推理仍是短板，需要 Agent（M5）。

## v3 留出集：泛化差距的第一次诚实测量（run 0040）

**协议**：5 家开发期间完全没有接触过的公司（万华化学 / 中国建筑 / 紫金矿业 /

不并入任何已有题目，拒答题换用另一组占位公司。
**评估只跑一次，结果不用于指导修改。**

| 指标 | v2（被看过 12 轮） | v3 留出集（第一次见） |
|---|---|---|
| 总体正确率 | 100% (182/182) | **96.7% [91.7, 100.0]** (58/60) |
| 表格数值题 | 100% | **100%** (38) |
| 口径辨析 | 100% | **100%** (8) |

| 量纲声明率 | 100% | 100% |
| 文档召回 / 页码召回 | 100% / 93.1% | 100% / 90.7% |
| 单题成本 | ¥0.0022 | ¥0.0021 |

### 泛化差距：3.3 个点

| | 开发集满分 | 留出集 | 差距 |
|---|---|---|---|
| v1 → v2 | 100% | 74.7% | **22.6 点** |
| v2 → v3 | 100% | **96.7%** | **3.3 点** |

**这是本项目最重要的一个数字。** 它回答了 7.19 留下的问题：
v2 的满分到底有多少水分。

答案是 3.3 个点——而 v1 那次是 22.6 点。两次的迭代轮次相近
（6 轮 vs 12 轮），差别在于**修复的性质**：

- v1 那六轮几乎全是往提示词里加规则 → 规则只对那 61 道题成立
- v2 这十二轮里消掉整类失败的是结构性修复（公司名改程序查表、
  三年表按年份展开、口径跨页继承、年份进检索文本）→ **改的是数据本身，
  所以跟着新公司一起生效**

此前把这条写成「有限的乐观理由，但不是证据」。**现在它有证据了。**

### 最有说服力的是这两类：表格数值 38/38、口径辨析 8/8

留出集的 38 道表格数值题和 8 道口径辨析题**全对**，
而这两类恰好是结构性修复覆盖的范围——按年份展开解决列归属，
跨页继承解决合并/母公司。新公司的年报里，这两套机制开箱即用。

对照：靠提示词规则支撑的两类（多跳的算术、拒答的边界判断）
各错一道，正是概率性手段该有的表现。

### 两个失败（已记录，不在此修复）

**① 万华化学的同比算错**：模型检索到的两个数都是对的
（203,234,573,814.42 与 182,069,119,160.94，正确答案 11.62%），
但算出 2.74%——没走 calculate 工具，心算错了。
提示词里「任何算术都必须走 calculate 工具」是概率性约束，压不住。

**② 问「海天味业」答成了「海康威视」**：语料里没有海天味业，
模型**贴到了最相近的已收录公司**。这比拒答严重得多——
用户拿到的是另一家公司的真实数字，表面上完全可信。
根因是查询分析要求「公司名逐字抄自可用语料」，
面对语料外的名字时模型选择了最相似项而不是留空。

### 这份留出集到此为止

上面两条若去修，v3 就从留出集降级为开发集，
**之后不能再用它声称泛化能力**。96.7% 这个数字就此冻结。
要再测一次，需要另建一份全新语料的 v4。

### 0030 这一行是个教训：总体没动 ≠ 没有效果

0030 相对 0029 点估计一模一样（97.3% → 97.3%），很容易据此判定
「汇总表提示没用」。但失败清单换了人：

```
0029 失败：格力2023现金流、海康2023现金流、恒瑞2023现金流、伊利2024营收、神华利润总额
0030 失败：格力同比、海康2023现金流、伊利2024营收、神华利润总额、茅台投资建议
```

格力与恒瑞的 2023 现金流**被修好了**，同时另外两道因别的原因失败，净值为零。
后来才查明：那版提示写死了上交所的措辞「近三年主要会计数据」，
而深交所的叫法是「主要会计数据和财务指标」——**它只覆盖了一半公司**。

**看汇总指标会得出「这个改动没用」，看失败清单才知道「它只做对了一半」。**

### 运行间波动

同配置多轮运行，总体正确率在 **97.3%–97.8%** 之间，相当于 1 道题的差异。
拒答类（n=15）波动更明显：误答率在 0% 与 6.7% 之间反复，
也就是一道题。**报告这类指标时应给出多轮区间，而不是最好的一次**
（安全相关的拒答尤其如此，见 `lessons.md` 7.15）。

### v1 的 100% 有多少水分：22.6 点

v1 上连续两次满分的同一套代码，换到 12 家语料的 v2 上只有 74.7%。
这个落差就是「对 61 道题调了六轮提示词」的代价，也是当初
**拒绝把满分写成「系统准确率 100%」的理由**。

分类看，落差集中在两处：

| 类别 | run 0028 | run 0029 | 说明 |
|---|---|---|---|
| 事实题 | 45.5% | 100% | 全是茅台题，被公司误判整类打掉 |
| 表格数值题 | 67.6% | 95.4% | 同上，叠加少量真实检索失败 |
| 多跳推理 | 100% | 100% | **Agent 直接泛化，32 题无一失败** |
| 口径辨析 | 75% | 100% | 新类；失败的 4 题同样是公司误判 |
| 应拒答 | 93.3% | 100% | |

**多跳 32/32 是这轮最值得说的结果**：M5 的 Agent 是在茅台和宁德时代上调出来的，
换 10 家新公司、换成自动生成的同比题，一道没错。

### 一个几乎瞒过去的缺陷：模型抄错了股票代码

run 0028 里茅台的题几乎全军覆没，且清一色「不应拒答却拒答了」。
打印中间状态才看到：

```
【贵州茅台的股票代码是多少？】
  filters = {'company_codes': ['600900'], ...}     ← 600900 是长江电力
  检索    = [(6, '600900_2025_annual'), ...]
```

查询分析让 LLM 直接输出六位股票代码。两家公司时不会错，十二家时开始串号。
**日志里只写「检索不到」，指标上只看到拒答率上升——所有线索都指向检索，
而错误发生在检索之前。**

修法：模型只输出公司名（逐字抄自语料清单），名字→代码由程序查表；
模型自己填的代码只在**用户原话里出现过**时才采信。
详见 `lessons.md` 7.11。

## v2 上的消融复验（run 0034 起）

v1 时期的三条结论——重排无效、强模型无收益、分块策略无影响——
**全部是在那个已知过拟合且饱和的评估集上测的**，必须在 v2 上重测。
下面三组都是单因子对照，共用同一份 heading 索引，无需重新入库。

| run | 配置 | 相对谁 | 单一差异 | 正确率 | 页码召回 | 单题成本 |
|---|---|---|---|---|---|---|
| 0033 | `exp00_debug` | — | 基准（flash，top_n=15） | 98.4% [96.2, 100.0] | 88.9% | ¥0.0020 |
| 0034 | `exp04_wider` | 0033 | 生成模型 flash → plus | 99.5% [98.4, 100.0] | 86.8% | ¥0.0087 |
| 0035 | `exp05_rerank_wide` | 0034 | 开启重排 | **93.4% [89.6, 96.7]** | 85.0% | ¥0.0091 |
| 0036 | `exp02_heading` | 0034 | top_n 15 → 5 | **84.6% [79.7, 90.1]** | **67.4%** | ¥0.0049 |

**三条结论里两条是区间不重叠的强结论**：截断深度有效（+14.9 点），
重排有害（−6.1 点）；强模型无显著收益但贵 4.3 倍。

### 截断深度：v1 的结论成立，机制也一样

exp02（top_n=5）对 exp04（top_n=15）掉 **14.9 个点**，区间完全不重叠
（90.1 < 98.4）。页码召回同步从 86.8% 掉到 67.4%——

**信息不是没检索到，是检索到之后被扔掉了。** 这与 v1 时分阶段测量的结论一致
（检索 top20 召回 95.9%，截断到 top5 只剩 44.9%），
在 12 家公司、182 题上重现。

代价是上下文变长：top_n=5 单题 ¥0.0049，top_n=15 为 ¥0.0087（同为 plus 模型）。
用 flash 跑 top_n=15 则只要 ¥0.0020——**宽截断 + 便宜模型是性价比最高的组合**，
这正是 `exp00_debug` 的配置。

分类看，窄截断对每一类都有损害，表格数值题跌得最多：

| 类别 | top_n=15 (0034) | top_n=5 (0036) | 差 |
|---|---|---|---|
| 表格数值题 | 99.1% | 81.5% | −17.6 |
| 多跳推理 | 100% | 90.6% | −9.4 |
| 口径辨析 | 100% | 81.2% | −18.8 |
| 事实题 | 100% | 90.9% | −9.1 |
| 应拒答 | 100% | 93.3% | −6.7 |

**口径辨析跌 18.8 点值得单说**：合并与母公司两张表在检索结果里相邻，
截断到 5 条时经常只剩其中一张，模型没得选只能用错的那张。
这类题对召回深度的敏感度最高。

### 四个因子的边际贡献（v2，取代 v1 的同名表）

| 因子 | 效果 | 区间 | 结论 |
|---|---|---|---|
| 截断深度 top_n 5→15 | **+14.9 点** | 不重叠 | **显著有效** |
| 重排 关→开 | **−6.1 点**，成本 +5% | 不重叠 | **显著有害，已关闭** |
| 生成模型 flash→plus | +1.1 点，成本 4.3 倍 | 大幅重叠 | 无显著收益，**用 flash** |
| 分块策略 heading→fixed | 未在 v2 上重测 | — | 需先按该策略重新入库（P2-5） |

**两个被广泛推荐的 RAG 手段（重排、强模型）在本场景一个有害、一个无收益；
真正起作用的仍是那个很少被讨论的参数：送进上下文的块数。**

### 重排不是「没用」，是显著有害

exp05 与 exp04 的区间**完全不重叠**（96.7 < 98.4）：开启重排掉 **6.1 个点**，
成本还高 5%。v1 上只能说「无显著差异」，v2 上可以说「显著变差」。

更有价值的是失败模式——它们指向同一个机制：

| 题目 | 正确答案（合并口径） | 开启重排后答出 |
|---|---|---|
| 茅台 2025 年总资产 | 303,834,844,021.44 | 195,350,142,529.19（**母公司**） |
| 宁德 2025 年合并资产总计 | 974,827,544 千元 | 643,206,871 千元（**母公司**） |
| 长江电力 2025 年归母净资产 | 221,338,010,639.92 | 177,345,840,006.15（**母公司**） |
| 海康 2025 年合并 / 母公司资产总计 | — | 两道都拒答 |

**重排系统性地把母公司报表排到了合并报表前面。**
口径辨析类从 100% 掉到 81.2%，是跌幅最大的一类。

机制是清楚的：gte-rerank-v2 是通用语义模型，而「母公司资产负债表」与
「合并资产负债表」在语义上几乎无法区分——它没有「合并是财务数据的默认口径」
这个领域常识，于是把 RRF 本来排对的顺序打乱了。
它的分数分布也印证这点（实测集中在 0.11–0.16，区分度极低）。

**这条比 v1 时「通用模型不如 RRF」的笼统说法硬得多：
不仅有区间不重叠的统计结论，还有可复现的失败机制。**

### 强模型：质量无显著差异，成本 4.3 倍

exp04（qwen-plus）99.5% 对 exp00_debug（qwen-flash）98.4%，
区间大幅重叠（[98.4, 100.0] vs [96.2, 100.0]），差异只相当于 2 道题；
而单题成本从 ¥0.0020 涨到 ¥0.0087。

**v1 上的结论在 v2 上依然成立，且语料从 2 家扩到 12 家后仍然成立。**

值得注意的是 exp04 唯一的失败与 exp00 的其中一个失败是同一道：
中国神华的「重述后/重述前」拆列表。**强模型也读错**——
说明那是结构问题而非模型能力问题（P1-6）。

## M5：Agent 分支上线（run 0016–0027）

多跳推理此前是最弱的一类（62.5%，n=8），这一轮围绕它做 Agent，
顺带暴露并修掉了四个与 Agent 无关的系统缺陷。

| run | 改动 | 总体正确率 | 多跳 | 页码召回 | 误答率 |
|---|---|---|---|---|---|
| 0014 | M4 最优（无 Agent） | 85.2% [75.4, 93.4] | 62.5% (5/8) | 86.7% | 8.3% |
| 0020 | 接入 Agent | 86.9% [78.7, 95.1] | 100% (8/8) | 89.8% | 16.7% |
| 0022 | + 合并/母公司口径、关键词去噪 | 93.4% [86.9, 98.4] | 100% | 91.8% | 8.3% |
| 0026 | + 拒答构词匹配、畸形工具调用拦截 | **100% [100, 100]** | 100% | 92.9% | 0% |
| 0027 | 同配置复跑 | **100% [100, 100]** | 100% | 94.9% | 0% |

单题成本 ¥0.0015，中位延迟 2.3 秒。

### ⚠️ 100% 要怎么读：评估集饱和了，不是问题解决了

**这个数字不能用来声称系统有 100% 的准确率。** 三条限制必须一起说：

1. **提示词是对着这 61 道题调出来的。** 从 run 0020 到 run 0026 共六轮，
   每轮都看错题、改提示词、再跑。这是标准的对测试集过拟合，
   泛化能力完全没有被验证。
2. **评估集已经失去判别力。** 满分意味着任何后续改动——无论变好变坏——
   在这个指标上都看不出区别。此后所有优化都是盲调，
   直到评估集扩大（P0-1，目标 320 题）为止。
3. **语料只有两家公司。** 这里的「口径」「列头」规则是从茅台与宁德时代的
   排版里总结的，换一家公司的年报模板是否还成立，没有证据。

正确的说法是：**在这 61 道人工核验过的题目上，经过六轮针对性修复后不再有失败案例**；
而不是「系统准确率 100%」。

### Agent 带来的与 Agent 无关的四个修复

真正有意思的是：围绕 Agent 做的这一轮，**大部分收益并非来自 Agent 本身**。

| # | 缺陷 | 性质 | 影响 |
|---|---|---|---|
| 1 | 年份只做标量过滤，没进检索文本 | 检索 | 三年并列表捞不出来，跨年问题全错 |
| 2 | 公司名留在 BM25 查询里 | 检索 | 文档内区分度为零却稀释权重，p6 摘要表跌出前 20 |
| 3 | 合并 / 母公司口径在解析时丢失 | 解析 | 两张现金流量表解析出的块逐字相同，模型只能靠猜 |
| 4 | 拒答词表枚举不全（漏了三轮） | 评估器 | 正确的拒答被记成误答，拒答能力的改进在指标上看不见 |

其中 1 和 2 是同一个认知的两面：**已经由标量过滤处理的字段不该再进检索文本，
而检索真正需要的字段必须进**。年份要进（列头里写着年份），公司名不该进
（每一页都写着公司名）。

#### 口径丢失是怎么被发现的

现象是「经营活动现金流量净额同比」算出 -11.43%，标准答案 -33.46%。
查下去发现模型取的是 326 亿，而正确值是 615 亿——差了近一倍。

直接去看两个块的原文，结论很干脆：

```
p64 块：第八节财务报告 > 二、财务报表 / 【单位：元】 / | 项目 | 附注 | 2025年度 | 2024年度 |
p66 块：第八节财务报告 > 二、财务报表 / 【单位：元】 / | 项目 | 附注 | 2025年度 | 2024年度 |
```

**逐字相同。** 一张是合并现金流量表，一张是母公司现金流量表，
而「合并」「母公司」这两个词在解析产物里一个字都没有——
标题只印在报表起始页，三大报表每张横跨两三页，续页没有任何标题。

这与「元 / 千元 / 万元」是同一类问题，解法也完全一样：**跨页继承**，
章节一变就失效（否则会把「合并」带进财务附注）。修完之后：

```
p64 块：合并现金流量表   → 经营活动产生的现金流量净额 61,522,204,989.35
p66 块：母公司现金流量表 → 经营活动产生的现金流量净额 32,618,216,666.91
```

### 评估集自身的两处缺陷（已修正）

修复失败用例时发现两道题**问法与标注自相矛盾**，模型答对反而被判错：

| 原问法 | 标注要的 | 问题 |
|---|---|---|
| 「销售净利率是多少」 | 归母净利润 / 营业收入 | 销售净利率的通行口径含少数股东损益，答 49.31% 并没有错 |
| 「财务报表使用的货币单位」 | 千元 | 「货币单位」也可以理解成币种，答「人民币」并没有错 |

两道都改了问法而不是改答案——**迁就模型的输出去改标准答案，等于把评估集变成橡皮尺**。

### 一个真实的 Agent 缺陷：文本形式的工具调用

run 0025 返回给用户的「答案」是这样一段：

```
calculate
{"expression": "82320067101.68 - 82293107655.25"}
</tool_call>
```

模型把工具调用写成了正文，结构化的 `tool_calls` 字段是空的，
而循环里「没有 tool_calls」被当成了「已经给出最终回答」。
现在按一次工具失败计数并要求重发，由护栏负责收敛。

**ReAct 循环的终止条件不能只看 `tool_calls` 是否为空**——
还得确认那段文本真的是回答。

### 运行间波动

同配置连续两次（run 0026 / 0027）总体正确率均为 100%，页码召回 92.9% / 94.9%。
但在满分之前波动是明显的：run 0024 为 98.4%、run 0025 为 96.7%，
失败的是不同的题（第三季度营收读错列、Agent 吐出畸形工具调用）。
**P0-3 的结果不稳定依然存在，只是被满分掩盖了。**

## 一个让三组实验全部作废的 bug

`run 0009`–`0011` 的数据已废弃，原因：

```python
# run.py
exp = load_experiment(args.exp)     # 读了 --exp 指定的配置

# 但节点内部
exp = load_experiment()             # 无参数，读的是环境变量 EXP_ID
```

**`--exp` 只影响评估记录，完全没影响实际运行的配置**，三组消融跑的全是基线。
当时的表现是「三个实验指标几乎一模一样」，而我差点据此断定
「重排和放宽截断都没用」——若就此收手，会彻底错过 +21.3 点的改进。

修法：实验配置随请求流转（`GraphState.exp_id` + `experiment_of(state)`），
禁止节点内直接调用无参的 `load_experiment()`。

**教训：配置必须随请求流转，不能走全局状态。**
全局配置在单实验时毫无问题，一旦要做横向对比就会静默失效——
它不报错，只是让所有实验悄悄变成同一个。

## 两个被修复的真实缺陷

### 1. report_year 语义错位（影响约四分之一题目）

`report_year` 是**文档的报告年度**，而用户问的是**数据的年度**。
一份 2025 年报含 2023–2025 三年数据，但 `report_year` 只有 2025，
用 `report_year == 2024` 过滤直接返回空集。

**排查时极易被误导**：因为在检索阶段就返回空，相关度阈值根本没被触及。
先前花了一轮去调阈值（0.02 → 0.010），「不应拒答却拒答了」反而从 14 条变成 15 条。

修法：查询年份展开为「该年份及其后两年」的报告年度。

### 2. RRF 分值阈值设置错误

RRF 分值的理论范围（k=60）：两路都排第一 = 2/61 = 0.0328，只有一路命中 = 1/61 = 0.0164。
阈值设成 0.02 会把「仅一路命中」的结果全部拒掉。

教训：**绝对阈值的含义随检索模式而变**。余弦相似度的 0.35 与 RRF 的 0.02 不可类比，
消融实验跨模式对比时必须重新校准，否则比较的是阈值而非检索质量。

## 当前瓶颈：检索排序，而非理解能力

run 0007 的 22 个失败中，13 个是「不应拒答却拒答了」。诊断两例：

```
问「销售净利率」→ 检索返回 p54(关键审计事项)、p16(行业经营性信息)、p72(财务报表)
                  而答案在 p6(主要会计数据)，模型正确地说「资料中未找到」

问「归母净利润」→ 检索返回 p62/p63/p107(财务报表附注)
                  虽含答案，但仍不是最权威的 p6 摘要表
```

**检索系统性地偏向财务报表附注（p60–120），而非摘要表（p6–7）。**
附注中科目名出现频率高，摘要表的 BM25 分数被稀释。这是排序问题，
重排（`exp03`）是针对性最强的下一步。

另：同一道题单独运行能答对、评估时却失败，再次印证 P0-3 的结果不稳定。

## 指标自身的缺陷：Recall@K 粒度过粗

当前 `Recall@K` 以 **doc_key** 为粒度——茅台年报的任何一个块命中都算 100%。
这让 93.9% 这个数字失去了判别力：它无法区分「检索到了 p6 摘要表」与
「检索到了 p150 的无关附注」，而后者正是当前的主要失败模式。

应改为**页码粒度**（评估集已标注 `expected_pages`，尚未启用）。
在此之前，Recall@K 只能用作「文档级过滤是否正确」的下限指标，
不能用来判断检索质量。

## 种子集时期的失败用例（run 0004，15 题）

4 个失败集中在两类，都是真实能力差距而非工程缺陷：

| 问题 | 期望 | 实际 | 性质 |

| 茅台2025年费用化研发投入 | 674,657,764.92 元（p12 管理层讨论） | 117,009,982.85 / 109,689,625.09 元（p205 财务附注） | **口径错配** |

两点值得注意：

1. **口径错配时模型是「认真答错」的**。它会详细解释为什么选这个科目——

   而在检索把口径不同的表排到了前面。这正是重排要解决的。
2. **同一道题两次运行答案不同**（117,009,982.85 与 109,689,625.09）。
   混合检索的 RRF 排序在边界上存在波动，会给评估引入噪声。
   扩大评估集时需要关注这一点，必要时多次运行取多数。

## 评估器自身的缺陷

评估器错了，所有指标都是假的。已踩过两次：

| 现象 | 原因 | 修正 |
|---|---|---|
| 误答率虚高到 50% | 拒答识别只收了「未找到」类说法，漏掉「我无法提供」「未在已收录的年报中出现」 | 补充标记词表 |
| 补完标记词后两道正确题反转为失败 | 全文匹配被回答末尾的免责声明误伤（「股票代码是600519……但无法提供实时行情」） | 改为只匹配**第一句**——真正的拒答第一句就表态 |

这两处都已被 `tests/test_m3_metrics.py` 用真实回答锁住。
**新增拒答表述时必须回跑历史用例确认没有反转。**
